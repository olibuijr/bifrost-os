# Agent API: the element map (0.4.77)

Agents (and tests, and scripts) drive BifrOSt by **name**, not by pixel. Every addressable thing in the OS and in apps is
listed in one map, generated by code from what already exists. Nothing is written by hand.

## Addresses
`scope/path/name`, from the labels the user sees, slugged by `bifrost_ui::ax::slug` ("Software Update" is `software-update`;
Icelandic letters fold to ASCII; a repeated name under one parent becomes `name-2`).

| Scope | Producer | Example |
|---|---|---|
| `os/settings/…` | every Settings page spec, walked from the root through each `Push` (`shell/axmap.rs`) | `os/settings/general/software-update` |
| `os/menubar/<menu>/<item>` | `menu_rows` of App, File, Edit, View, Window, Help (`desktop_bar.rs`) | `os/menubar/edit/select-all` |
| `os/apps/<app>` | `apps()` (built in and installed); value `open` when a window exists | `os/apps/settings` |
| `app/<app-id>/<role>/<name>` | a running app's semantic nodes (`ToShell::Controls`) | `app/is.olibuijr.files/button/new-folder` |

An element has: address, name, role (`page`, `toggle`, `slider`, `choice`, `text`, `menu`, `item`, `app`, `button`, `field`,
`list`, `row`), value (a switch is `on`/`off`), enabled, and a producer handle that says how to act on it.

## Commands
Shell control socket (127.0.0.1:7777) and `tools/midget.py`:

```
midget.py ax [prefix]      list the map (tab separated: address role name value enabled)
midget.py press NAME       press by full address, by path ("General > Software Update"), or by a unique name
```
`press` answers `ok <address>`, or `error:` with `no element`, `is ambiguous: a b c`, `is disabled`, `cannot be pressed yet`.
A Settings press is exactly the tap path (sidebar row, then each row down the page stack); a menu press is `run_menu_action`;
an app press is a tap at the node's centre sent to the app process.

## Closed-loop commands (autonomy)
An agent should never guess a delay or a pixel. These replace both:

```
midget.py wait NAME [--value V] [--enabled] [--gone] [--timeout S]   block until the element shows up / has that value / is gone
midget.py ota [--timeout=S]                                          the whole OS update, by name, then confirm the guard accepted it
```
- **State is live.** Settings pages come from the same source the screen is drawn from (`Settings::spec_for`), so the Software
  Update page lists `check-for-update`, `download-and-install` or `install-now` depending on the updater, and values (a switch is
  `on`/`off`) are current.
- **Alerts are elements.** An open confirmation is `os/settings/alert` (value = its title, `message` below it) with
  `cancel` and the confirm button named after the action (`download`, `restart`, `check`, `roll-back`). While an alert is open any
  other Settings press answers `error: an alert is open: answer it first`, as a real tap would be blocked.
- **`ota`** unlocks, opens Software Update, presses whatever the updater offers (check, download, install), confirms each
  sheet, waits for the restart, unlocks, and waits for `bifrost-update-guard` to say `accepted`. It handles the case where the page
  lags behind a device that is already `system-prepared`. It reports `up to date` when there is nothing to install.

## How apps appear
- An app that declares `App::controls()` is mapped from that.
- Otherwise the kit's draw helpers record what they draw (`widgets::toolbar`, `source_list`, `popup_button`, `text_field` call
  `bifrost_ui::ax::record`), so an app on the kit is mapped with no code. The SDK runtime sends the recording as the controls.
- An app with its own drawing declares an element with one call: `bifrost_app::controls::ax::record(role, label, value, bounds, enabled)`
  in its draw (the same as `accessibilityLabel` on a custom `UIView`). Bounds are window-local points.

## Apple parity and gaps (record, per the standing rule)
Reference: `NSAccessibility` / `UIAccessibility`, `AXUIElement`, App Intents.
- Done: stable identifiers, label, value, enabled state, role, frame, press (`AXPress`), unique-name lookup.
- Gap: hierarchy. The map is a tree by address, but app nodes are flat (4 roles: button, field, list, row).
  Missing roles: toggle, slider, menu item, static text, window. Wire format has no id for them; add roles by appending values.
- Gap: values can be read but not set (`AXValue` set): sliders and text fields need `ax set`.
- Gap: Settings pages that depend on a selection (a Wi-Fi network's detail) are not listed.
- Gap: Window controls (close, minimise), the dock's pinned order and the status icons are not mapped yet.
- Gap: **App Intents** (typed, discoverable actions that need no UI: `AppIntent`, `AppEntity`, `AppShortcut`). The app control
  socket (`bifrost pc control`) is the nearest thing: `rpc` methods with names. Next: declare intents in the manifest with typed
  parameters and let `ax`-style addressing list them as `app/<id>/intent/<name>`.
- Gap: most apps draw their own views and declare nothing yet; only Files is mapped. Coverage is measured by
  `midget.py ax app/` with the app open.
