# QA pass, 2026-10-10 (Midget, shell 0.4.98, apps latest)

Tester pass on Midget (10.99.0.200) after round 39. Each item: what was seen, where to look, severity.

## Critical

1. **Term runs a root shell.** The prompt is `[root@bifrost /]#`, in `/`. Term must spawn the login shell as the local
   account (uid from `/var/lib/springboard/account`) in its home, like the sandboxed apps (`bare/app_policy.rs`).
   Code: `src/term/pty.rs`, `src/shell/terminal.rs`.
2. **Updates rebooted during mkinitcpio** (fixed in 0.4.97: guard `apply` waits for ESP `pending=0` and no
   `db.lck`; `tools/midget.py` waits too). Still to do: the shell's Settings > Software Update path must use `apply`
   only, and the guard should refuse `system-prepared` reboots from any caller until staged (done in `apply`).
3. **Store installer read keys inside `[[intent]]` tables** (fixed in 0.4.98, `store/install.rs`). Audit every other
   manifest reader (`bare/app_policy.rs` `Manifest::parse`, `tools/*.py`) for the same bug.

## High

4. **Stale presenter content.** A closed window's last frame (a Photopea-like web page with Windows-style controls)
   stays drawn behind Files; no process owns it. The 7 px dark band under the left menu bar (bottom of the 28 pt bar,
   x 0 to the end of the menu titles) is the same class: pixels from an earlier popup or window are never cleared on
   the GPU path. Code: `src/gpu/wl.rs`, `src/bare/wayland.rs`, `desktop_bar.rs` `desk_regions_now`.
5. **Failed app launch leaves a black window.** After the rollback, `cannot start is.olibuijr.files.desktop: No such
   file or directory` left a black placeholder that later took focus and swallowed `open-app`. A failed spawn must
   remove the window and show an alert. Code: `shell/apphost.rs:708`.
6. **Duplicate menus.** An app that publishes `main_menu` shows `Notes File Edit File Edit View Window Help`: the app's
   File/Edit are added beside the shell defaults instead of replacing them (merge by title, NSApp.mainMenu).
   Code: `desktop_bar.rs` `Menu::Custom`.
7. **Spotlight shortcuts cannot reach apps.** The SDK falls back to `appdata/<id>/control.sock` because the sandbox
   has no `XDG_RUNTIME_DIR`; `shell/intents.rs` only looks in `$XDG_RUNTIME_DIR/bifrost/apps/`. Use one resolver for
   both. Also: the socket answers only its own uid (root gets ECONNRESET), and `bifrost pc control` cannot reach
   Midget's apps at all (add a `--midget` path over ssh).
8. **Apps do not follow Dark.** Switching to Dark turns Files dark, but Notes and Calculator stay light; Files' content
   area is pure black instead of the window background `Pair`.

## Medium

9. **Menu separators invisible.** Separator rows in bar menus draw an empty gap, no hairline (Notes File, Term Edit).
10. **Menus survive context changes.** Esc in one app, then `open-app` another, left the Edit menu open over Files.
11. **`key enter` opened the RAM menu** (`menu=Some(Memory)`): Return activates a status item without focus intent.
12. **RAM menu content.** Low-contrast grey on a pale pink material; "Top apps by memory" lists Notes at 0.00 GB.
13. **Term:** Undo is enabled although Term has nothing to undo; a dark empty strip sits between the title bar and the
    tab strip; the tab caption says `~` while the shell is in `/`.
14. **Rollback restore window.** Right after a rollback, `/var/lib/springboard` is briefly unavailable and app launches
    fail with ENOENT (see 5); launches should wait for the state mount.

## Works

- System 0.4.98 accepted after probation; all store apps at the latest version.
- App-published menus open, show key equivalents, disable correctly (Delete Note), and run the action (New Note).
- App Intents over the control socket: `intent.list`, `intent.evaluate` → `{"value":14,"dialog":"2+3*4 = 14"}`.
- Term Edit menu shows the new Find, Find Next/Previous and Clear Scrollback items with keys.
