# Parity wave 6, batch b17

Branch `parity/w6-b17` on top of `main` (release 0.5.36). Closes three gap rows with pure-Rust models and leaves
the rest of the gap rows open, each with a reason. Not built or run here: the lead builds once at the end.

## What was built

1. **`concurrent_perform`** in `springboard/sdk/src/dispatch.rs`. Mirrors `DispatchQueue.concurrentPerform(iterations:execute:)`:
   `body(i)` runs once for each `i` in `0..iterations`, over up to `available_parallelism` scoped threads, and the call
   returns when all calls finish. It does not use the shared queue pool. Five tests in `perform_tests`.
2. **`EventJournal`, `Replay`, `SINCE_NOW`** in `springboard/sdk/src/fswatch.rs`. The event-id part of a change stream:
   ids start at 1, the newest `capacity` events are kept, `replay_since(id)` returns later events and says whether
   anything was dropped. In memory only, so no replay across a restart. Six tests in `journal_tests`.
3. **`inspect`, `ImageProperties`, `ImageContents`** in `springboard/ui/src/disk_image.rs`. Reads the ISO 9660 primary
   volume descriptor (sector 16): volume name, declared block count and block size, declared size, and whether the
   file is at least that long. Anything else is reported as raw. Five tests in `inspect_tests`.

Official API names mirrored: `DispatchQueue.concurrentPerform(iterations:execute:)`; event ids of the change stream
(the latest event id and the since-now id); `DiskImage` properties. The ISO 9660 layout is a file format (ECMA-119),
not an Apple API.

## Rows skipped

- core-bluetooth, "Channel Sounding (distance measurement)": needs an LE Channel Sounding controller. No hardware here.
- core-bluetooth, "Background execution and Live Activity privileges": needs a per-app Bluetooth background policy and
  link lifecycle in `springboard/src/bare/bluetooth.rs`. Not built in this batch.
- core-services, "Apple Events (inter-process messages with replies)": needs a typed message transport with reply
  descriptors between apps. Larger than this batch; the control socket is a different design.
- cryptotokenkit, "Smart card token driver and token": needs a token driver extension mechanism and smart card hardware.
- disk-arbitration, "Session and run loop or dispatch queue scheduling (DASession)": needs a live disk event source to
  feed sessions. The existing models in `springboard/core/src/disk_events.rs` are pure and not fed by one.
- disk-arbitration, "Volumes in the Files sidebar": a UI change in the Files app, and grants do not reach mounted
  volumes (`springboard/src/bare/docbroker.rs`). Not built here.
- dispatch, "Target queues" (`setTarget(queue:)`): the pool's queue kinds would need redesign. Not built.
- dispatch, "Dispatch I/O channels": needs low and high water marks over file descriptors. Not built.
