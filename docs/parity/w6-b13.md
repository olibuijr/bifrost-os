# Parity wave 6, batch b13: media accessibility, media library, iTunes Library

Branch `parity/w6-b13`, from `main` (release 0.5.36). Pure Rust, std only, no builds run in this batch (the lead builds
once at the end). The six matrix files were read: itunes-library, media-accessibility, media-intelligence,
media-library, media-player, now-playing. Matrix files are not edited here.

## What was built

- **Flashing lights detection and dimming** (new module `springboard/ui/src/flashing_lights.rs`). Reads timed
  luminance samples, finds reversals with a swing of at least 0.10, counts a flash per reversal after the first, and
  flags a sequence with more than 3 flashes in any one-second window. With dimming on, flagged output is scaled by 0.6.
  Mirrors the enabled setting and the processor of the official flashing-lights topic.
  Gap: no framebuffer capture (the caller supplies samples); the flash count is a simplified reversal count, not the
  full pair-of-transitions rule.
- **Library load keys** (`springboard/ui/src/media_sources.rs`, `LoadOptions::from_keys`). Absent folders key loads
  folders; absent include and exclude keys apply no filter. Mirrors the load keys for folders, include sources and
  exclude sources.
- **Library entry point state and unload** (`springboard/ui/src/media_changes.rs`, `MediaLibrary::is_loaded`,
  `MediaLibrary::unload`). Unload drops the snapshot and the modification time; the next listing reports every item as
  inserted. Mirrors the load, reload and unload life cycle of the library entry point.
- **Change notification** (`springboard/ui/src/media_changes.rs`, existing `MediaLibrary::observe`). Returns a change
  only while notifications are on, so no new code was needed for this row.

Tests: flashing_lights 8 tests, media_sources 7 tests, media_changes 7 tests. All expected values were worked out by hand
from the rules (for example, a 10 Hz square wave gives reversals at 100 to 900 ms and eight flashes in one window).

## Official API names mirrored

- Media Accessibility: `MADimFlashingLightsEnabled()`, `kMADimFlashingLightsChangedNotification`,
  `MAFlashingLightsProcessor` (topic "Flashing lights", https://developer.apple.com/documentation/mediaaccessibility/flashing-lights).
- Media Library: `MLMediaLibrary`, load keys `MLMediaLoadFoldersKey`, `MLMediaLoadIncludeSourcesKey`,
  `MLMediaLoadExcludeSourcesKey` (https://developer.apple.com/documentation/medialibrary). The framework is marked
  deprecated in favour of PhotoKit and the iTunes Library framework.
- iTunes Library: `ITLibrary` entry point with `reloadData`, `unloadData`, `apiVersion` (only the first two
  are modelled), `DidChangeLibraryMessage` (https://developer.apple.com/documentation/ituneslibrary).

## Rows skipped

| Framework slug | Feature | Reason |
|---|---|---|
| itunes-library | Video media info (ITLibMediaItemVideoInfo) | The library is audio-only and no video metadata source exists in pure code; fields would be invented. |
| media-intelligence | On-device ML analysis runtime (shared by all requests) | Needs an inference runtime and models. None exists in BifrOSt; the hamr project is separate. |
| media-intelligence | Errors (MediaIntelligenceError) | Depends on analysis operations, which do not exist yet. |
| media-player | Media picker (MPMediaPickerController) | A picker is a view controller. Pure logic would only repeat list selection that the existing list and table models cover. |
| media-player | External player items (MPContentItem, MPPlayableContentManager) | The playable content manager is deprecated by Apple, and publishing needs a system delivery path that does not exist. |
| now-playing | Remote sessions: RemoteMediaSession, extension, attributes, MediaDevice | Needs a remote device transport and an extension host. Nothing in pure code can stand in for them. |
