# Parity wave 6, batch b10: Metal, MPS, Model I/O, PDFKit, PencilKit, Quartz

Pure Rust models in `springboard/ui/src` (bifrost-ui). None is wired into the shell or the SDK yet, and none has run
on the VM or Midget. Each row below moves from gap to partial only, and only for the model's scope.

## What was built

- `springboard/ui/src/shader_library.rs`: a named table of shader entry points (vertex, fragment, kernel), with
  identifier and uniqueness checks, exact lookup, and render and compute pipeline checks that require the right stage.
  It compiles no shader and holds no source.
- `springboard/ui/src/pdf_overlay.rs`: one overlay per PDF page with a frame in page points, the set of displayed
  pages with start and end reports for overlays, markup mode, and hit testing that is active only in markup mode.
- `springboard/ui/src/pdf_access.rs`: the PDF access permission word (encode and decode of the eight operation bits and
  the reserved bits), write option checks that refuse restrictions or passwords because encryption is not performed,
  and the effective permissions of a document without an encryption dictionary.

Each module has a `#[cfg(test)] mod tests` block with behaviour tests worked out from the rules in its header.

## Official API names mirrored

- Metal: `MTLLibrary` (`functionNames`, `makeFunction(name:)`, `makeFunction(descriptor:)`) and `MTLFunction`.
  Source: https://developer.apple.com/documentation/metal/mtllibrary
- PDFKit: `PDFPageOverlayViewProvider` (`pdfView(_:overlayViewFor:)`, `pdfView(_:willDisplayOverlayView:for:)`,
  `pdfView(_:willEndDisplayingOverlayView:for:)`), `PDFView.isInMarkupMode`.
  Source: https://developer.apple.com/documentation/pdfkit/pdfpageoverlayviewprovider
- PDFKit: `PDFDocument.accessPermissions`, `PDFDocumentWriteOption` (write options with permissions and passwords).
  Source: https://developer.apple.com/documentation/pdfkit/pdfdocument/accesspermissions
- The bit layout of the permission word follows ISO 32000-2 (PDF 2.0), not an Apple page. The Apple page names the
  property only.

## Rows skipped

| Framework slug | Feature | Reason |
|---|---|---|
| metal | Machine learning passes | Needs a GPU inference path (tensor operations in a command encoder). There is no device to run it on in pure Rust. |
| metal-performance-shaders | Kernel base classes and keyed archiving | Not built in this batch. A kernel base model would need a design pass against the official MPSKernel pages first. Next wave. |
| model-i-o | Sharing buffers with the GPU framework | The consumers named (MetalKit, GLKit, SceneKit) are Apple-only, and the Linux GL path has no 3D consumer to share with. |
| pencilkit | Handwriting recognition (PKStrokeRecognizer) | Needs a trained recognition model. A stroke-to-text model is not honest in pure Rust without one. |
| pencilkit | Scribble on non-text views | Needs pen input hardware and text-input routing into arbitrary views. |
| quartz | Quartz Composer compositions and custom patches | Needs a node-graph runtime and plug-in host. The framework is deprecated, so this batch did not build it. |
