# Parity wave 6, batch b09: ColorSync, Core Animation, Core Graphics, Core Image, GameplayKit, GLKit

Branch `parity/w6-b09`, started from main at 0.5.36. No build was run; the lead builds once at the end.

## What was built

Two new pure modules in `springboard/render/src`, std only, each with a `#[cfg(test)] mod tests` block.

- `reusable_layer.rs` (`ReusableLayer`): an offscreen pixel buffer that a caller draws into with `draw(|surface| ..)`.
  The surface starts at row 0 with stride equal to the width, earlier content is kept, and `draws()` counts the passes.
  Mirrors the reference offscreen layer object (`CGLayer`: create with a size, `size`, a drawing context). The reference
  `context` accessor is replaced by the `draw` closure, because a Rust borrow cannot be returned from a layer.
- `lazy_image.rs` (`LazyImage`, `RenderContext`): an image is a source plus a chain of named filters from
  `effect_chain`. `apply` consumes the image and returns one with one more filter. `RenderContext::render` runs the chain
  once and returns the pixels, or `None` when the buffer does not match the width and height. Mirrors the reference
  image object (lazily evaluated) and its render context (`CIImage`, `CIContext`).

`springboard/render/src/lib.rs` gained two `pub mod` lines (`reusable_layer`, `lazy_image`).

## Official API names mirrored

- CoreGraphics: `CGLayer`, `init(_:size:auxiliaryInfo:)` (creating the layer), `CGLayer.size` (https://developer.apple.com/documentation/coregraphics/cglayer).

## Verification (hand-worked)

- `ReusableLayer::new(0,4)` is `None`; a 3 by 2 layer reports size (3, 2) and six zero pixels.
- A draw passes a surface with w=3, h=2, stride=3; the draw count is 1.
- Pixel at row 1, column 2 of a width-3 layer is index 1*3+2 = 5.
- A second draw keeps the earlier pixel at index 0 and sets index 5; the draw count is 2.
- `LazyImage` with no filters renders the source unchanged.
- One stop of exposure (ev = -1) on packed 0xff34_64c8 (R 200, G 100, B 52) gives R 100, G 50, B 26, so 0xff1a_3264.
- Two stops give R 50, G 25, B 13, so 0xff0d_1932. The quantiser is `(v*255 + 0.5) as u32`, so the halvings round exactly.
- Applying a filter does not change the base image: base has 0 filters and still renders 0xff34_64c8; the derived image renders 0xff1a_3264.
- A 3 by 2 source reports extent (3, 2); a 2 by 2 source with 3 pixels does not render (`None`).
