# Parity wave 6, batch b01: gap rows closed in pure Rust

Branch `parity/w6-b01`, on top of release 0.5.36. Nine framework files were in scope (bundle-resources,
core-foundation, evaluations, foundation-models, music-understanding, observation, paperkit, permissionkit,
relevancekit). They hold ten rows with status `gap`. Four rows are closed as `partial` here. Six rows are skipped
with reasons. No row is `parity`: none of this code has run on the host or on Midget yet.

## What was built

All code is pure Rust with std only. No unsafe, no new crates, no I/O, and no network.

1. **Time clues** (`springboard/ui/src/relevance.rs`). `TimeClue` mirrors the time-clue constructors of
   `RelevantContext`: `at` (a single date), `interval` (start included, end excluded), `range` (both ends included)
   and `between` (`date(from:to:)`, default hint). `DateKind` has `Default`, `Informational` and `Scheduled`.
   `score_at(base, now)` adds the hint's offset to the base score while the clue is active.
   The official pages name the three hints but give no amounts. The offsets (+1.0, -0.5, 0) and the one-hour
   window for a point clue (`POINT_CLUE_SECONDS`) are local choices and are documented as such in the module.
2. **Model-judge evaluators** (`springboard/ui/src/evaluation.rs`). `ScoreDimension` (name, weight, scale),
   `ModelJudgePrompt` (a template with `{input}`, `{expected}`, `{response}`, `{dimension}`, `{min}`, `{max}`,
   filled in one pass), `parse_score` (reads the line `<dimension>: <number>` inside the scale) and
   `model_judge`, which returns an ordinary `Evaluator`. The judge is a closure supplied by the caller, so the
   model itself can be any model. The score is the weighted mean of the normalized dimensions. A judge error or
   an unreadable reply scores NaN.
3. **Output guardrail** (`springboard/ui/src/guardrail.rs`, new file). `Guardrail` holds a character limit and a
   list of blocked phrases. `check` passes a text through or refuses it with `GuardrailError`. `redact` replaces
   the blocked phrases with a mask. Matching ignores ASCII case only. This is a list-based screen, not a classifier.
4. **Permission button** (`springboard/ui/src/permission_question.rs`, re-exported from
   `springboard/sdk/src/permission_kit.rs`). `PermissionButton<T>` sends its question once, reads the answer back
   and reports a `ButtonState` (`Ready`, `Waiting`, `Answered(choice)`, `Expired`). `collect` takes the answer out of
   the `AskCenter`. Two methods were added to `AskCenter`: `response_for` (read without removing) and
   `take_response` (remove one answer by question id). Nothing draws the button yet.

Tests: each changed or new module has a test module. Time clues have 5 tests, model judge 6, the guardrail 7 and
the permission button 5. Expected values were worked out by hand from the rules in the code (for example, a
weighted score of (3 + 0.5) / 4 = 0.875). Nothing has been compiled or run, per the batch rules.

Owner name guard: `python3 tools/check-names.py` exits 0 on this branch.

## Official API names mirrored

- RelevanceKit: `RelevantContext.date(_:)`, `date(_:kind:)`, `date(interval:kind:)`, `date(range:kind:)`,
  `date(from:to:)`, `RelevantContext.DateKind` (`default`, `informational`, `scheduled`).
  Sources: https://developer.apple.com/documentation/relevancekit (DocC via `tools/parity/docc.py`) and
  https://developer.apple.com/documentation/relevancekit/relevantcontext/datekind.
- Evaluations: the names in the matrix row (`ModelJudgeEvaluator`, `ModelJudgePrompt`, `ScoreDimension`) are mirrored
  by `model_judge`, `ModelJudgePrompt` and `ScoreDimension`. The DocC pages for the judge types were not read
  in this batch, so the signatures are not checked against the official ones.
- Foundation Models: guardrail errors for generated output (the safety-guidance page). The DocC page was not
  read in this batch; the error model is local and follows the row text only.
- PermissionKit: `PermissionButton` with `init(question:label:)` and its `question` and `body` properties
  (https://developer.apple.com/documentation/permissionkit/permissionbutton). The async permission-flow initializer
  (`init(question:permissionFlow:onPermissionResult:label:)`) is not mirrored; there is no permission-flow type.

## Rows skipped (status stays `gap`)

- **bundle-resources: Universal links service (applinks)**. The official `applinks` details (keys, the app list
  and the path patterns) are not in the DocC pages that `docc.py` could fetch (the child pages return 404). A
  verification format written from memory would be invented. The routing model already exists in
  `springboard/core/src/app_links.rs`, but nothing checks an association file.
- **core-foundation: Plug-ins and bundles (CFPlugIn, CFBundle)**. Loading a plug-in means loading a shared library,
  which needs unsafe code and a loader policy. The pure-Rust, no-unsafe rule rules it out. Resource lookup already
  exists in `springboard/sdk/src/bundle_resources.rs`.
- **foundation-models: On-device system language model (SystemLanguageModel)**. It needs a local model runtime and
  model weights. Neither is in the SDK or the shell, and this batch has no hardware or model access.
- **music-understanding: Instrument activity**. Per-instrument activity needs source separation, which is a learned
  model, not a rule that pure Rust can check honestly here.
- **observation: Observable conformance (@Observable macro)**. The synthesis of change notification for every stored
  property needs a derive macro or a procedural macro. Both need a proc-macro crate, and the rules allow no new
  crates. `springboard/ui/src/observe.rs` covers the whole-value wrapper only.
- **paperkit: Adornments over markup**. `MarkupAdornment` has an anchor, an image configuration, a drag region and a
  zoom flag. The DocC pages for the anchor, drag-region and image-configuration cases were not reachable (404), so
  their cases are unknown and a model would be a guess. The shell draws its own chrome (`springboard/src/shell/markup.rs`).
