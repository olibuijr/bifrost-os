# Parity wave 6, batch b19

Scope: the eight frameworks in batch b19 (local-authentication, metrickit, network, network-extension,
open-directory, os, service-management, system-configuration). Nine rows had status `gap`.

## Built

- `springboard/sdk/src/synchronization.rs`: `UnfairLock<State>` (a type alias of the existing scoped `Mutex`
  under the `OSAllocatedUnfairLock` name) and `stateless_unfair_lock()` for the `init()` form. Five new tests in
  `unfair_lock_tests`. Only the closure-scoped API is provided. The unscoped `lock()` and `unlock()` need a guard
  held across calls, which needs `unsafe`, so they are not modelled. The `flags:` hints and `Ownership`/`precondition`
  are not modelled either, because the std mutex has no equivalent.

## Official API mirrored

- `OSAllocatedUnfairLock`, `init()`, `init(initialState:)`, `withLock(_:)`, `withLockIfAvailable(_:)`
  (https://developer.apple.com/documentation/os/osallocatedunfairlock, macOS 13.0). The page was read with
  `tools/parity/docc.py os/osallocatedunfairlock`.

## Rows skipped

| Framework slug | Feature | Reason |
|---|---|---|
| local-authentication | Authentication prompt UI (LocalAuthenticationView) | SwiftUI view. The Rust shell has no SwiftUI. The state model in springboard/ui/src/auth_view.rs is the existing counterpart and is not extended here. |
| metrickit | GPU and Metal frame metrics (GPUTimeMetric, MetalFrameRateMetric) | Needs GPU timing counters from the driver. No hardware access allowed. |
| network | Privacy attribution and local network identity | Needs per-app network attribution from the network stack. This needs the network daemon and privileged access. |
| network-extension | Hotspot helper | Needs a hotspot or access-point subsystem and a helper process. None exists, and none can be built without hardware or a network service. |
| network-extension | App extensions host (NEAppExtensionConfiguration) | Needs an extension host process and a network-extension provider. Network service required. |
| open-directory | Contacts search in LDAP or Open Directory | Needs an LDAP server. Network service required. |
| service-management | Embedded helper executables | BifrOSt has no embedded login-item or helper bundle layout (see springboard/sdk service_management docs). Needs a bundle format decision first. |
| system-configuration | Ethernet bond and VLAN interfaces | Needs kernel netlink configuration of bonds and VLANs. The matrix notes this is a server-class target outside the desktop network model. |
