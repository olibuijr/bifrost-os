# Parity wave 6, batch b16: CryptoKit AES-GCM and CFNetwork FTP

Status: built, not yet compiled or tested. The lead builds once at the end of the wave; no build ran in this round.

## What was built

- `springboard/core/src/aes_gcm.rs` (module `bifrost_core::aes_gcm`): AES-128 and AES-256 block encryption
  (FIPS-197) and AES-GCM seal and open (NIST SP 800-38D), pure std, no unsafe. The S-box is derived at first use from
  the GF(2^8) inverse and the affine map. Nonces are 12 bytes, tags are 16 bytes, and the sealed box is ciphertext
  followed by tag. `open` compares the tag in constant time. Table lookups on the S-box can leak timing; the module
  doc says so.
- `springboard/sdk/src/ftp.rs` (module `bifrost_app::ftp`): a pure FTP model. It parses ftp:// URLs (user, password,
  port 21 default, percent-decoded path), parses single and multi-line replies with their RFC 959 class, reads PASV
  (227) and EPSV (229) data addresses, formats control commands and refuses arguments with CR, LF or NUL, and parses
  Unix long-format directory listings into entries (name, kind, size, mode bits, owner, group, modification stamp).
  It opens no socket.

## Official API names mirrored

- CryptoKit: `AES`, `AES.GCM`, `AES.GCM.Nonce`, `AES.GCM.SealedBox`, `seal(_:using:nonce:authenticating:)`,
  `open(_:using:authenticating:)`. The mirrored behaviour is the GCM construction. The key type (`SymmetricKey`) is
  not added.
- CFNetwork: `CFFTPCreateParsedResourceListing(_:_:_:_:)` and the `kCFFTPResource*` dictionary keys (name, size,
  mod date, mode, owner, group, type, link) map to `Entry`, `Stamp` and `Kind`. The stream calls
  (`CFReadStreamCreateWithFTPURL`, `CFWriteStreamCreateWithFTPURL`) are not mirrored as streams; the model gives the
  URL, reply, command and listing pieces a transport needs.
- Apple marks `CFFTPCreateParsedResourceListing` deprecated in favour of the URL loading API. This model is for legacy
  file servers. The URL loading API in `springboard/sdk/src/url.rs` does not support FTP yet.

## Tests written (not run)

- `aes_gcm`: FIPS-197 appendix C block vectors (AES-128 and AES-256), GCM test cases 1 and 2 (empty message and one
  zero block), S-box entries 00, 01 and 53 from FIPS-197 section 5.1.1, GF products from section 4.2, a hand-derived
  check that an empty message tag equals E(nonce || 00000001), round trip with additional data, tamper and wrong
  additional data rejection, key and nonce length errors, and the GF(2^128) identity element.
- `ftp`: URL parsing with escapes and defaults, scheme and port errors, single and multi-line replies with their
  classes and the unterminated case, PASV and EPSV address parsing (port 50000 from 195,80), command line format and
  the CR/LF/NUL refusal, and a listing with a total line and a dot entry (directory, file with year, symlink with
  target; modes 0o755, 0o644, 0o777).

Run on the lead's build: `cargo test -p bifrost-core aes_gcm` and `cargo test -p bifrost-app ftp`.
