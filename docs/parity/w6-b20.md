# Parity wave 6, batch b20: Authentication Services

Closes two of the four `gap` rows in `docs/parity-matrix/data/authentication-services.json`. Both are pure models in
`springboard/ui/src` (bifrost-ui), with host unit tests. Neither is wired into apps or the shell, and neither has been
tested on the VM or Midget.

## What was built

### Authorization requests (`springboard/ui/src/authorization_request.rs`)

- `AuthorizationController` holds the requests a provider created (`RequestKind::Password`, `RequestKind::Passkey`),
  performs them once, and ends in one phase: an `AuthorizationResult`, a failure with a reason, or a cancel.
- `AuthorizationResult` is the password or passkey outcome. Its `Debug` output redacts the password.
- Refused calls return `ControllerError` (no requests, performed twice, not performing, result kind not requested).
- Mirrors: `ASAuthorizationController` (`init(authorizationRequests:)`, `performRequests()`, `cancel()`,
  `authorizationRequests`), the `ASAuthorizationResult` cases and the `ASAuthorizationRequest` kinds that this model
  carries. Not mirrored: presentation context, custom authorization methods, AutoFill-assisted requests, delegate
  callbacks, and Sign in with Apple.

### AutoFill credential identities (`springboard/ui/src/credential_identity.rs`)

- `IdentityStore` holds `CredentialIdentity` records (service, user, record identifier, rank, kind). Its operations
  are save (replaces a record of the same identifier and kind), remove, replace, remove all, and set enabled. Switching
  the store off clears it and refuses changes, as the system does when the extension is disabled.
- `identities_for` fetches the identities of the selected kinds (`IdentityTypes`) that cover a `ServiceIdentifier`,
  ordered by rank (highest first), then user name, then record identifier.
- Matching: a URL or domain identifier covers a query whose host equals it or is a subdomain of it. An app identifier
  matches only the same identifier.
- Mirrors: `ASCredentialIdentityStore` (store state, `saveCredentialIdentities`, `replaceCredentialIdentities`,
  `removeCredentialIdentities`, `removeAllCredentialIdentities`, `credentialIdentities(forService:credentialIdentityTypes:)`),
  `ASCredentialServiceIdentifier` (`URL`, `domain`, `app` identifier types), `ASCredentialIdentity` (`rank`, `user`,
  `recordIdentifier`, `serviceIdentifier`) and `ASCredentialIdentityStore.IdentityTypes`.
  Not mirrored: the QuickType suggestion bar, the extension process, passkey-specific fields, the asynchronous
  completion handlers (calls return values directly), and the deprecated password-only methods.

The lib.rs declarations are `pub mod authorization_request;` and `pub mod credential_identity;`, placed after
`pub mod one_time_code;`.

## Rows skipped

- **Single sign-on in a web browser app** (gap). The official page describes the browser handing an authentication
  request from another app and returning the session. That needs the browser app in `springboard/apps/browser` to
  broker between processes, route callbacks and keep its own cookie store. None of this is a pure model, and the
  handoff protocol is not in the official pages read here. Needs a browser-side change first.
- **Credential import and export** (gap). The official page names `ASCredentialExportManager` and the `ASImportable*`
  types, but the wire format (CXF) is not described in the official pages read. Building it would mean writing the
  format from memory, which the official-docs rule does not allow. Skipped until the format's authoritative
  description is available.
