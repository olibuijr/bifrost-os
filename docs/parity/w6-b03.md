# Parity wave 6, batch b03

Closes gap rows in Combine, Contacts and Core Data, and mirrors their official API names. Built in pure
Rust with std only. Not built or run in this round: the lead builds once at the end. Not wired into apps or the
shell, and not yet tested on the VM or Midget.

## What was built

### Async publisher sequence (Combine)

- `springboard/sdk/src/async_publisher.rs`: `AsyncPublisher<T, E>`, the alias `AsyncThrowingPublisher<T, E>`,
  and `Step<T, E>` (`Value`, `Finished`, `Failed`, `Pending`).
- Attaches to a `PassthroughSubject` (`from_subject`) or replays a `Finite` publisher (`from_finite`).
- `next()` never blocks. It returns `Pending` while nothing is buffered and the publisher is open, so the
  sequence can be pulled from a shell or app loop. Rust has no async runtime here, so the `for await` form is
  not offered.
- Mirrors: `AsyncPublisher`, `AsyncPublisher.Iterator`, `AsyncThrowingPublisher`.

### Contact display defaults (Contacts)

- `springboard/ui/src/contact_display.rs`: `SortOrder` (`None`, `UserDefault`, `GivenName`, `FamilyName`),
  `sort_contacts`, `compare_names`, `normalize_country_code`, `ContactsDefaults`.
- Mirrors: `CNContactsUserDefaults` (`sortOrder`, `countryCode`) and `CNContactSortOrder`.
- Limits: there is no shared `shared()` singleton. The shell owns one `ContactsDefaults` value and passes it to
  the views that need it. No preference is persisted yet.

### Object graph and persistent store (Core Data)

- `springboard/sdk/src/object_graph.rs`:
  - `Model`, `Entity`, `Attribute`, `AttributeType`, `Relationship`: checked when built. Inverses must exist
    on the destination and point back.
  - `Container`: holds the model and the store. `new`, `open(model, text)`, `to_text`, `new_context`, `version`.
  - `Context`: a working copy. `insert`, `set`, `value`, `link`, `unlink`, `targets`, `delete`, `fetch`,
    `changes`, `has_changes`, `rollback`, `save`.
  - `Store`: the saved objects with a version and a text format (`springboard-store-v1`).
- Edges are kept on both ends. A to-one link replaces its old target, and a to-one inverse drops its old source.
- Dirty tracking compares each object with the copy the context read. Save is optimistic: a context whose version
  is stale gets `Error::Conflict`. A save that fails required-attribute checks changes nothing.
- Mirrors: `NSPersistentContainer` (`Container`), `NSManagedObjectContext` (`Context`),
  `NSManagedObjectModel`, `NSEntityDescription`, `NSAttributeDescription`, `NSRelationshipDescription`.
- Limits: the store is one text file, not SQLite. Every object is loaded (no faulting). There is no
  undo in a context, and merge policies are reduced to refuse-on-conflict.

## Tests

- `async_publisher.rs`: 7 tests (send order, no replay of earlier values, detach on drop, finite
  completion once, failure then end, never-completing stays pending, `drain_ready`).
- `contact_display.rs`: 7 tests (user-default resolution, country code validation, given-name order with
  case folding, family-name order, `None` keeps order, equal names keep input order, defaults and country
  replacement).
- `object_graph.rs`: 10 tests (model inverse check, typed values, inverse on one-side link, to-one replacement,
  wrong destination refused, delete removes incoming links, required attribute on save, conflict and rollback,
  text round trip with escaping, damaged text refused with its line).
