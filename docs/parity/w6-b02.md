# Parity wave 6, batch b02: gap rows of Swift, SwiftData, Symbols, Accounts, Address Book, App Intents

Scope: every row whose status was `gap` in `docs/parity-matrix/data/{swift,swiftdata,symbols,accounts,address-book,app-intents}.json`
at release 0.5.36. Pure Rust, std only, no builds in this round. The lead updates the matrix.

## What was built

- `springboard/sdk/src/actor.rs` (new, `bifrost_app::actor`): `Actor<S>` is a value owned by its own thread. `tell`
  queues a message, `ask` queues one and waits for the reply, and messages run one at a time in send order. A
  panicking message stops the actor (`ask` then returns `None`). Five tests.
- `springboard/ui/src/symbol_layers.rs` (new, `bifrost_ui::symbol_layers`): the layer rules that sit beside the
  effects in `symbol_effect.rs`.
  - Variable colour: `Fill` (cumulative, iterative), `Inactive` (dim, hide), `Playback` (non-reversing, reversing),
    `cycle_progress` and `layer_opacity`.
  - Weight: `Weight` with nine steps, `stroke_factor` 1.0 at Regular, 0.15 per step.
  - Scale: `Scale` (small, medium, large) with `factor`.
  - Rendering modes: `RenderingMode` (monochrome, hierarchical, palette, multicolor), `rendering_opacity`
    (hierarchy steps 1.0, 0.5, 0.3), `palette_slot`.
  - Nine tests, each value worked out by hand from the rule in the code.
- Registered with one `pub mod` line each in `springboard/sdk/src/lib.rs` and `springboard/ui/src/lib.rs`.

Not wired into the renderer, the glyph drawing or any app yet. The rules are pure functions.

## Existing modules that cover rows (no new code this round)

- `springboard/ui/src/contact_groups.rs` (`bifrost_ui::contact_groups`): a tree of named groups with subgroups,
  membership, recursive member lists, cycle refusal on move, subtree removal and forgetting deleted contacts.
  Six tests exist. The matrix still lists the Groups row as gap, so this closes it as partial here.
- `springboard/ui/src/contact_picker.rs` (`bifrost_ui::contact_picker`): the picker model, with contact mode and
  property mode, a need filter, disabled entries, search and the returned choice. Seven tests exist. The person view
  side is `springboard/ui/src/contact_card.rs`, which was not re-read in this round.

## Rows skipped

- swift, "Distributed actors": needs calls between processes through a transport service. A socket service is a
  new network-facing daemon, which is outside this batch.
- swiftdata, "Sync of model data across a person's devices (iCloud)": needs a sync service on the network.
- accounts, "BifrOSt account sign-in (cloud)": the account lives on the bifrost-cloud server (separate repo). The
  SDK side needs a network client and a sign-in flow, which are not pure Rust in this scope.
- app-intents, "Widgets, controls and Live Activities": needs a widget extension host and system surfaces that the
  SDK does not have. `springboard/sdk/src/widgets.rs` is a drawing adapter, not an extension point.
- app-intents, "Schema domains and visual presentation": needs a system schema registry, hardware button routing
  and a visual search service. None exist on the device.
